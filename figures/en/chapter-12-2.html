Layer 1: Solver and compute backend (Solver / Backend Layer)• Produces the raw solve status, variable solution values, objective value, bounds and low-level mathematical evidence (IIS/duals, etc.)
↓
Layer 2: OSPF base framework layer (Base Framework Layer)• Encapsulates the unified orthogonal SolveReport, stable model element IDs, evidence capability grades, the mathematical model fingerprint (Fingerprint) and the composite solve attempt trace (Attempt Trace)• Boundary: understands only generic mathematical reports and algebraic diagnostics, and does not know which order is late or which machine conflicts
↓
Layer 3: Algorithm layer and APS/DOP application layer (Algorithm & Application Layer)• Algorithm layer: keeps the mathematical semantics and maps element IDs back to domain variables, constraint templates, objectives and intermediate values• Application layer: binds mathematical evidence to concrete business objects (order/production line/task/location), frozen version snapshots, business KPI comparisons and tenant permission boundaries
↓
Layer 4: Workbench presentation layer and agent layer (Presentation & Agent Layer)• Visualizes feasibility, KPI breakdown, slack and the conflicting constraint set (IIS) in the workbench• The agent summarizes authorized structured evidence, compares candidate plans and explains in localized business language• Iron rule: the agent must never rewrite the solve status, never invent an IIS, and never override a hard constraint with a confidence score!
